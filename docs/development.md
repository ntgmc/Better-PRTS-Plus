# 开发与验证

安装文件 `Better-PRTS-Plus.user.js` 由 `src/` 中的源码按顺序拼接生成，运行在同一个闭包中。修改源码后重新构建，不直接编辑安装文件。

## 模块边界

| 路径 | 职责 |
| --- | --- |
| `src/core/utils.js`、`constants.js` | 通用值校验、配置定义与旧配置迁移 |
| `src/core/account-state.js` | 账号数据规范化、迁移与纯状态转换 |
| `src/core/http.js` | JSON 多源下载、超时和取消其余请求 |
| `src/core/release-manifest.js`、`script-updates.js` | 版本比较、更新清单与提醒 |
| `src/core/filter-scheduler.js` | 合并延迟、动画帧和待处理卡片 |
| `src/core/page-sync.js` | 页面结构同步、路由变化、DOM 监听与诊断 |
| `src/dom/react.js`、`card-resolution.js` | React 数据读取与 DOM 回退解析 |
| `src/dom/page-enhancements.js` | 卡片头像、描述、关卡交互、弹层与公告增强 |
| `src/filter/operation-matching.js`、`card-filter.js` | 阵容及练度匹配、卡片状态与统计 |
| `src/import/` | 名单解析、账号存储、备份和森空岛接口与签名 |
| `src/ui/` | 通用控件、名单导入、筛选栏、森空岛面板和级联设置 |
| `src/styles/` | 公共及 PRTS 样式、森空岛样式、可选全站样式 |
| `src/data/` | 内置生成数据与热更新 |
| `src/main.js` | 等待页面正文就绪，初始化当前站点 |

`tool/userscript-sources.json` 是唯一的源码顺序清单，构建和核心测试共用。增加或移动源码时同步修改清单；测试会检查重复项、漏项和完整脚本语法。初始化时执行的代码应放在所依赖的状态和常量定义之后。

## 页面更新

PRTS 页面使用一个 DOM 观察器收集受影响的卡片、页面结构和弹层。卡片内部文字变化只更新对应卡片；页面结构变化才同步工具栏等页面控件。弹层同时支持已有节点、嵌套插入和延迟填充，创建和编辑页面也可显示干员组头像。

观察器忽略脚本自己的工具栏、弹窗、状态提示和弹层网格，避免界面输出触发重复处理。三秒兜底同步保留，后台标签页跳过；路由变化取消旧的筛选任务并触发完整刷新。

筛选协调器保留已经排队的动画帧，立即刷新会吸收已有延迟任务。局部更新可以只重算统计，已移除的卡片不会使所有剩余卡片重新匹配。设置、账号及路由变化仍会完整检查当前列表。

卡片数据优先读取当前 React Fiber，避免相同文字掩盖练度要求或作业类型变化。只有 DOM 回退解析计算卡片文字签名。一次匹配内，同一条干员要求的练度结果只计算一次；不同干员组中的独立要求分别检查。

## 本次重构的页面测量

2026-10-26 使用真实 `https://prts.plus/`、Chromium 153、1280 × 720 视口，对重构前的 `e29b759` 与当前构建各测三轮。顺序为旧、新、新、旧、旧、新；每轮新开页面，使用内存版 `GM_*`，预置资源缓存、432 名干员和完美阵容筛选。脚本仅临时注入函数计数，产品代码不包含测量逻辑。

每轮从 10 张卡片开始，预热 1 秒后计数；空闲 3.2 秒，加载更多到 20 张并等待 0.3 秒，搜索 `1-7` 并等待 1 秒，再清空搜索并等待 1 秒。下表为整个计数区间的结果，耗时取 CDP `Performance.getMetrics` 的全页 `ScriptDuration` 差值。

| 指标 | 重构前的三轮 | 重构后的三轮 |
| --- | --- | --- |
| 卡片处理次数 | 100 / 90 / 90 | 60 / 60 / 60 |
| 卡片全文签名扫描次数 | 100 / 90 / 90 | 0 / 0 / 0 |
| 页面结构同步次数 | 13 / 13 / 13 | 10 / 10 / 10 |
| 全页脚本耗时（毫秒） | 265.5 / 259.0 / 255.9 | 246.7 / 237.0 / 251.9 |

全页脚本耗时中位数为 259.0 → 246.7 毫秒。该样本确认重复处理减少；请求时序、原站渲染和浏览器状态仍会影响整页耗时，不能据此推断其他页面、长时间运行或所有设备的收益。本轮未采集长任务或堆内存。

## 活动关卡快捷浮窗

`tool/update-activity-data.js` 从国服游戏数据的 `activity_table.json`、`zone_table.json`、`stage_table.json` 生成 `resources/activities.json`。运行 `node tool/update-activity-data.js` 更新；也可传入包含这三份文件的目录进行离线生成。环境变量 `GAME_DATA_REF` 可指定游戏数据提交，默认使用 `master`。自动更新见下文“跟随上游更新资源”。

活动使用 `startTime` / `endTime`，不使用 `rewardEndTime`；分区使用 `zoneValidInfo`，并与活动和 `stageValidInfo` 的时间取交集。按关卡代号区分普通、EX、S 和其他关卡，同一类别开放时间不同时分别显示。复刻通过 `zoneToActivity` 关联当前活动，保留原始关卡 ID 和地图路径。仅收录有战斗地图、代号且难度为 NORMAL 的关卡，避免剧情节点和突袭重复按钮。

PRTS 页面先从油猴缓存显示日程，页面启动时立即检查更新，之后每小时检查一次；JSON 请求禁用浏览器缓存，下载失败保留已有日程。页面同步会检查活动及分区边界，按钮点击时再次核对开放时间。`src/ui/activity-shortcuts.js` 复用原站筛选器，只更改关卡条件；浮窗变化由 DOM 观察器忽略。设置关闭后停止日程下载，重新开启即时恢复已有日程。

多个活动同时开放时，通过顶部下拉框切换，每次只渲染一个活动的分区。首次显示优先定位当前筛选关卡所属活动，否则采用日程中最新开启的活动。选择按活动 ID 保存在当前页面会话中，路由往返和日程更新会保留；仅当原站关卡筛选值变化时跟随定位，避免例行同步撤销手动切换。当前活动结束或从日程移除时回退到仍有效的活动，剩余一个活动时隐藏切换器，全部结束时移除浮窗。关卡解析兼容原始关卡 ID 和地图路径，按钮状态只使用所选活动的分区，避免跨活动重复关卡 ID 覆盖开放状态。切换器节点独立于关卡内容，切换或例行同步不会替换它；切换活动会重置关卡列表滚动位置。

在作业列表打开悬浮球，按住 **Shift** 点击“设置”标题，即可显示“诊断”。点击“模拟活动”会使用原站已收录的前两个含普通、EX 或 S 战斗关卡的活动生成测试浮窗（只有一个时使用一个）：普通关和 EX 关立即开放，S 关一分钟后开放，模拟持续一小时。点击关卡会实际更新原站筛选。点击“结束模拟活动”、关闭模拟浮窗或刷新页面可退出；模拟期间临时显示测试浮窗，不改动真实日程缓存及浮窗显示偏好。

## 跟随上游更新资源

`Update resources` 工作流同时追踪 `Kengxxiao/ArknightsGameData` 的 `master`（模组及活动）和 `ZOOT-Plus/zoot-plus-frontend` 的 `dev`（干员）。`tool/resource-upstream.js` 通过 GitHub API 读取两个分支的提交号。每 15 分钟检查一次；同一组提交已同步成功时，跳过下载、生成和项目检查。GitHub 定时任务可能延迟，这不是实时推送。

工作流也接收 `repository_dispatch` 事件 `upstream-resources-updated`，可由上游或已有 webhook 服务触发：

```sh
gh api --method POST repos/ntgmc/Better-PRTS-Plus/dispatches \
  -f event_type=upstream-resources-updated
```

发送方需要对本仓库有内容写入权限的 GitHub App 或访问令牌。第三方仓库的 push 不会自动触发本仓库的 Actions；需要在上游配置通知或通过现有服务转发。本项目不额外部署 webhook 服务，也不新增访问令牌。尚未配置发送方时，定时检查仍会自动跟进更新。

每次更新将两个提交号固定到下载地址，游戏活动的三张表及镜像回退使用同一个游戏数据提交。资源提交后调用 jsDelivr purge 接口刷新 `data.json` 和 `activities.json`，并下载镜像文件与仓库文件逐字节比对，避免客户端读取分支镜像的旧缓存。生成、项目检查、资源提交和镜像刷新全部成功后，才通过 Actions 缓存记录这一组提交；失败不会标记成功，下次检查继续尝试。缓存键包含生成脚本及工作流内容，修改同步逻辑也会触发重新生成。缓存被清理时会重新运行完整同步。

手动运行工作流和事件通知都会强制执行完整同步，可用于修正资源或重试，不受成功缓存限制。资源日程直接发布到 `main`，不需要发布新的用户脚本版本；客户端页面启动时检查活动日程，之后按每小时检查下载。

## 本地检查

需要 Node.js 和 PowerShell 7。在仓库根目录运行：

```powershell
pwsh -File tool/build-userscript.ps1
pwsh -File tool/check.ps1
```

只运行核心回归：

```sh
node tool/test-core.js
```

检查包括源码与安装文件一致性、JavaScript 语法、核心行为回归、README 版本号，以及 DOM 渲染和凭据持久化的安全边界。核心测试覆盖旧数据迁移、写入失败、跨页面账号更新、破坏性导入确认、阵容与练度、筛选统计、级联设置、资源及脚本更新、页面监听和筛选调度。

筛选栏布局和卡片标题限高的范围见 [设计记录](../design.md)。修改后可使用本机已有的 Playwright 与 Chromium 运行真实页面回归：

```sh
PLAYWRIGHT_MODULE=/path/to/playwright \
BROWSER_PATH=/path/to/chromium \
PRTS_REVIEW_OUTPUT=/tmp/prts-style-review \
node tool/check-site-redesign.js
```

已安装标准 Playwright 时可省略前两个变量。该检查会访问 `https://prts.plus` 的公开页面，使用隔离上下文和内存版 `GM_*`，阻止非只读请求；覆盖三种原站主题及 320、375、414、768、1024、1440px，核对筛选栏换行、卡片标题两行限高、设置和导入窗口的视口限制，以及搜索、作业集切换、取消和样式开关。默认与悬停状态分别对照开关前后的实际颜色、边框和阴影，确保局部布局不改动原有视觉。截图和 `report.json` 保存在输出目录，仍需实际查看关键截图。

改动页面同步时，还应在浏览器验证搜索、加载更多、作业集抽屉、创建页往返和窄屏设置。真实页面验证可使用内存版 `GM_*` 接口；森空岛真实登录和油猴扩展环境需要单独验证。性能结论应依据对照测量，不能仅从减少函数调用推断整页耗时下降。历史试验见 [页面同步测量](page-sync-performance.md)。
