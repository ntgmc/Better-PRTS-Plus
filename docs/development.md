# 开发与验证

安装文件 `Better-PRTS-Plus.user.js` 由 `src/` 中的源码按顺序拼接生成，运行在同一个闭包中。修改源码后重新构建，不直接编辑安装文件。

## 模块边界

| 路径 | 职责 |
| --- | --- |
| `src/core/utils.js`、`constants.js` | 通用值校验、配置定义与旧配置迁移 |
| `src/core/account-state.js` | 账号数据规范化、迁移与纯状态转换 |
| `src/core/http.js` | JSON 多源下载、超时和取消其余请求 |
| `src/core/release-manifest.js`、`script-updates.js` | 版本比较、更新清单与提醒 |
| `src/core/filter-scheduler.js` | 合并延迟、动画帧和待处理卡片 |
| `src/core/page-sync.js` | 页面结构同步、路由变化、DOM 监听与诊断 |
| `src/dom/react.js`、`card-resolution.js` | React 数据读取与 DOM 回退解析 |
| `src/dom/page-enhancements.js` | 卡片头像、描述、关卡交互、弹层与公告增强 |
| `src/filter/operation-matching.js`、`card-filter.js` | 阵容及练度匹配、卡片状态与统计 |
| `src/import/` | 名单解析、账号存储、备份和森空岛接口与签名 |
| `src/ui/` | 通用控件、名单导入、筛选栏、森空岛面板和级联设置 |
| `src/styles/` | 公共及 PRTS 样式、森空岛样式、可选全站样式 |
| `src/data/` | 内置生成数据与热更新 |
| `src/main.js` | 等待页面正文就绪，初始化当前站点 |

`tool/userscript-sources.json` 是唯一的源码顺序清单，构建和核心测试共用。增加或移动源码时同步修改清单；测试会检查重复项、漏项和完整脚本语法。初始化时执行的代码应放在所依赖的状态和常量定义之后。

## 页面更新

PRTS 页面使用一个 DOM 观察器收集受影响的卡片、页面结构和弹层。卡片内部文字变化只更新对应卡片；页面结构变化才同步工具栏等页面控件。弹层同时支持已有节点、嵌套插入和延迟填充，创建和编辑页面也可显示干员组头像。

观察器忽略脚本自己的工具栏、弹窗、状态提示和弹层网格，避免界面输出触发重复处理。三秒兜底同步保留，后台标签页跳过；路由变化取消旧的筛选任务并触发完整刷新。

筛选协调器保留已经排队的动画帧，立即刷新会吸收已有延迟任务。局部更新可以只重算统计，已移除的卡片不会使所有剩余卡片重新匹配。设置、账号及路由变化仍会完整检查当前列表。

卡片数据优先读取当前 React Fiber，避免相同文字掩盖练度要求或作业类型变化。只有 DOM 回退解析计算卡片文字签名。一次匹配内，同一条干员要求的练度结果只计算一次；不同干员组中的独立要求分别检查。

## 本次重构的页面测量

2026-10-26 使用真实 `https://prts.plus/`、Chromium 153、1280 × 720 视口，对重构前的 `e29b759` 与当前构建各测三轮。顺序为旧、新、新、旧、旧、新；每轮新开页面，使用内存版 `GM_*`，预置资源缓存、432 名干员和完美阵容筛选。脚本仅临时注入函数计数，产品代码不包含测量逻辑。

每轮从 10 张卡片开始，预热 1 秒后计数；空闲 3.2 秒，加载更多到 20 张并等待 0.3 秒，搜索 `1-7` 并等待 1 秒，再清空搜索并等待 1 秒。下表为整个计数区间的结果，耗时取 CDP `Performance.getMetrics` 的全页 `ScriptDuration` 差值。

| 指标 | 重构前的三轮 | 重构后的三轮 |
| --- | --- | --- |
| 卡片处理次数 | 100 / 90 / 90 | 60 / 60 / 60 |
| 卡片全文签名扫描次数 | 100 / 90 / 90 | 0 / 0 / 0 |
| 页面结构同步次数 | 13 / 13 / 13 | 10 / 10 / 10 |
| 全页脚本耗时（毫秒） | 265.5 / 259.0 / 255.9 | 246.7 / 237.0 / 251.9 |

全页脚本耗时中位数为 259.0 → 246.7 毫秒。该样本确认重复处理减少；请求时序、原站渲染和浏览器状态仍会影响整页耗时，不能据此推断其他页面、长时间运行或所有设备的收益。本轮未采集长任务或堆内存。

## 本地检查

需要 Node.js 和 PowerShell 7。在仓库根目录运行：

```powershell
pwsh -File tool/build-userscript.ps1
pwsh -File tool/check.ps1
```

只运行核心回归：

```sh
node tool/test-core.js
```

检查包括源码与安装文件一致性、JavaScript 语法、核心行为回归、README 版本号，以及 DOM 渲染和凭据持久化的安全边界。核心测试覆盖旧数据迁移、写入失败、跨页面账号更新、破坏性导入确认、阵容与练度、筛选统计、级联设置、资源及脚本更新、页面监听和筛选调度。

改动页面同步时，还应在浏览器验证搜索、加载更多、作业集抽屉、创建页往返和窄屏设置。真实页面验证可使用内存版 `GM_*` 接口；森空岛真实登录和油猴扩展环境需要单独验证。性能结论应依据对照测量，不能仅从减少函数调用推断整页耗时下降。历史试验见 [页面同步测量](page-sync-performance.md)。
